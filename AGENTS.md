# AGENTS.md

Universal instructions for AI agents in **regira** (Regira front-end library: TypeScript +
Vue 3). Single source of truth for all agents (Claude, Copilot, Codex, …); `CLAUDE.md` just points here.

## 1. Keep documentation in sync (first priority)

Docs are layered and describe the same modules at different altitudes — keep them consistent.
Edits are **bidirectional**: change one layer, update its counterparts in the same turn.

| You change… | Also update… |
|-------------|--------------|
| `src/<m>/README.md` | that module's `ai/*.md` (matching sections) |
| `src/<m>/ai/*.md` | `src/<m>/README.md`; `ai/module.json` if scope/description changed |
| `src/<m>/docs/*.md` | the module's `ai/*.md` and `README.md`. These and `README.md` are also the **published** docs site (§7) — their content is copied into it as written (only relative links are rewritten — §7), so anything you write there goes public on the next push to `main` |
| Root `README.md` index | the module set on disk (and vice-versa) |
| A public signature/behavior in `src/**` | every doc layer that documents it — `…signatures.md` must match the built `dist/**/*.d.ts` (`npm run build`) |
| A `src/vue/ui` component `_template/ui/manifest.json` lists | its ejectable copy — run `npm run build` in the same change. `_template/**` is committed build output, and the manifest tells apps to import their ejected copy, so a stale one ships the bug the release says it fixed |
| Any user-visible change | `CHANGELOG.md` (bullet under *Unreleased*) + the `package.json` version (§8) |

If a counterpart edit is out of scope, say so explicitly rather than leaving layers inconsistent.

**Write docs in final state, not as a diff.** Don't narrate a history of changes — no changelogs,
"previously…/now…", "fixed", "updated", or migration notes. Update each document as if it had just
been authored cleanly, with no record of prior errors or revisions.

## 2. Layout

- **Core:** `src/{utilities,extensions,treelist,events,io}`. **Vue:** `src/vue/{entities,http,ioc,auth,ui,app,lang,formatters,directives,online,debug}` + `src/vue/vue-helper.ts` (code; its docs live in `src/vue/vue-helper/`).
- Each module: `README.md` (developer docs) + `ai/` = `<m>.instructions.md`, `<m>.signatures.md`, `<m>.examples.md`, `module.json`, and optionally `<m>.card.md` (the hand-authored index card the MCP serves via `get_package_card`; entities and auth ship one). Entities adds `namespaces.md`, `patterns.md`, `setup.md`, `template.md`, `shell.template.md`, `attachments.template.md`, `advanced.example.md`, `blueprints.md`, a `docs/` folder, and `vue-entities-agent.md` at the module root —
a Claude Code sub-agent definition, deliberately outside `ai/` because that folder is the MCP's knowledge
base and this is tooling. Nothing here loads it: it is in neither `package.json` `files` nor a
`.claude/agents/` folder, so an app that wants the persona copies the file into its own `.claude/agents/`.
- Root `README.md` indexes all modules; each is published via a `package.json` `exports` subpath (`@regira/modules/<m>`).
- `dist/**/*.d.ts` = authoritative public API. Generated by `npm run build`, **not committed** — the
  `prepare` script builds it before `npm publish` and on git-dependency installs; run the build
  locally when you need it.
- **Meta package:** `src/bootstrap/ai/` (`frontend.bootstrap.md` + `module.json`, id `regira_modules`) holds the *front-end consumer bootstrap* — the SPA routing entry the MCP serves as `get_package id="regira_modules" section="frontend.bootstrap"`. Documentation-only: no `src` code, no `package.json` `exports` subpath. Distinct from this `AGENTS.md`/`CLAUDE.md`, which guide agents *working in* this repo.
- **Docs site:** `docs/` is a self-contained VitePress project (its own `package.json` and `node_modules`) — see §7. Hand-authored: `docs/index.md` and `docs/guide/*.md`. Everything under `docs/reference/`, plus `.vitepress/sidebar.json`, is **generated and `.gitignore`d** — edit the module's `README.md` / `docs/*.md`, never the copy under `reference/`.

## 3. Commands

`npm run dev` · `npm run build` (writes `dist/` + `.d.ts`) · `npm run types` · `npm test` (Vitest) ·
`npm run format` (Prettier).

Docs site — from `docs/`, which has its own dependencies (`cd docs && npm install` once):
`npm run docs:dev` · `npm run docs:build` · `npm run docs:preview`. The first two run `sync-modules.mjs`
before VitePress, so they pick up module doc edits without a separate step.

## 4. Conventions

- **Never guess** a signature, import path, or option — verify against the built `dist/**/*.d.ts`
  (run `npm run build` if `dist/` is absent) and the module's `ai/*.signatures.md`/`namespaces.md`.
  If unconfirmed, ask; don't invent.
- After changing a public type, rebuild and reconcile `ai/*.signatures.md` with the new `.d.ts`.
- Match local style; import across modules via their `exports` subpath, not deep relative paths;
  run `npm run format` before finishing.
- **Cross-module links in `ai/*.md` stay source-tree relative** — `](../../http/ai/http.instructions.md)`.
  They are read two ways, and this form serves the one that has a file system: a contributor browsing
  the repo. Over the MCP an agent gets the text without a tree to resolve against, so the path is inert
  there rather than misleading — it names the guide it means. Do **not** convert them to
  `get_package(...)` calls. Regira-Packages does the opposite for a reason that does not apply here:
  its guides are **extracted** into a consumer's flat `.regira/instructions/`, where a `../../` path
  points at a directory that exists and holds something else. Nothing in this repo is extracted
  (`package.json` `files` is `["dist","_template"]`), so the two conventions are both correct.
- **Dormant — don't use:** `src/entities/*` (commented-out; use `@regira/modules/vue/entities`),
  `src/identity/*` (legacy), and `src/firebase/*` (legacy — still exported from the root
  barrel and the `./firebase` subpath). All three are indexed in the root `README.md` with a
  dormant marker, but remain don't-use.

## 5. Adding/renaming/removing a module

Update together: `src/<path>/README.md` + `ai/` set (incl. `module.json`), the root `README.md` index,
`package.json` `exports`, and the `MODULES` array in `docs/sync-modules.mjs` (§7) — that list is
hand-maintained, and the sync skips an unknown module with a warning instead of failing, so a module
left out of it is simply absent from the published site with a green build.

The `src/bootstrap/ai/` meta package (front-end consumer bootstrap) is the exception: update its `ai/` set
only. It is served by the MCP (§6), has **no `package.json` `exports` entry** (not a runtime subpath), and
is **not** listed in the developer `README.md` (which stays purely developer-facing — agent docs and
developer docs never cross-reference).

## 6. MCP

`https://mcp.regira.com/mcp` serves these modules; its knowledge builder reads each `ai/*.md` + the
built `.d.ts` from `dist/`. Since `dist/` is not committed, **the knowledge build must be preceded by
`npm run build`** — without it the `.d.ts` scan silently yields nothing. Stale `ai/*.md`/`module.json`
degrades what every agent sees — hence §1.

## 7. Docs site (developer-facing)

`https://regira.github.io/Regira-Modules/` — the VitePress site in `docs/`, the developer counterpart to
the MCP's agent guides. `.github/workflows/deploy-docs.yml` rebuilds and deploys it on every push to
`main` touching `docs/**` or `src/**`, so a module doc edit publishes itself; there is no release step.

`docs/sync-modules.mjs` runs before every build and copies each module's **`README.md` + `docs/*.md`**
from `src/` into `docs/reference/<id>/`, rewriting relative links to the site's flat routes and writing
`.vitepress/sidebar.json`. Nothing is duplicated in git — the canonical markdown stays in `src/**`, and
`reference/` plus `sidebar.json` are `.gitignore`d. Two consequences worth holding on to:

- **A stale `docs/reference/` on disk is a local build artifact, not drift.** Re-run the sync rather than
  reconciling it by hand, and never edit a file under `reference/` — the next build overwrites it.
- The site sets `ignoreDeadLinks`, because module docs legitimately link to source files that have no
  published page. A broken link therefore **will not** fail the build; check links in `src/**` yourself.

## 8. Versioning & releases

The whole library ships as one npm package; its `version` lives in `package.json` (SemVer).
Published npm versions are **immutable** — never reuse or overwrite one.

- **Any user-visible change** — module code, `_template/**`, the `ai/*.md` guides — must
  leave `version` **higher than the last published release**: patch for fixes and doc-only changes,
  minor for backward-compatible features, major for breaking changes. If the version was already
  bumped since the last publish, several edits may share that bump.
  A guide edit counts even though `package.json` `files` is `["dist","_template"]`, so no `ai/*.md`
  reaches an npm consumer: the guides ship through the MCP knowledge build (§6), which runs off a
  release, and the version is what tells it there is something new to ingest. Skipping the bump on a
  doc-only change leaves every agent on the previous text.
- **Record every user-visible change in [CHANGELOG.md](CHANGELOG.md) in the same change**: one
  bullet under `## Unreleased`. On release, the Unreleased block becomes a `## x.y.z — YYYY-MM-DD`
  heading.
- Publishing runs via `.github/workflows/publish-npm.yml` (version tag or manual dispatch). It
  refuses to publish when the tag and `package.json` disagree, the version already exists on npm,
  or the changelog lacks the release heading.

Release/deploy mechanics for the wider Regira toolchain live outside this repository.

## 9. Code Reviews

When writing a report, present it as a single markdown block or give the user a link that he can open.
The content of the report should always be (temporarily) accessible to the user.

## 10. Git

Commit or push only when the user explicitly asks. Leave finished work in the working tree and report
what is ready — a review verdict ("ready to commit") or a checklist step is not that ask.
